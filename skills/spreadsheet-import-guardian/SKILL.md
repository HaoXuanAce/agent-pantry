# 表格导入守卫

“能读出 Excel”不等于导入可靠。编码、单元格类型、数字精度、重复上传和部分失败都可能悄悄污染业务数据。本 Skill 把表格导入当成有版本、有验证、有恢复能力的数据接口。

## 边界

处理 CSV/XLSX 模板、解析、字段映射、校验、预览、提交、错误反馈和安全导出。临时数据分析、制作图表、复杂 Excel 公式建模不在范围内。

涉及身份证号、手机号、银行卡号等敏感字段时，只使用脱敏样例和最小必要日志。

涉及 CSV 导出或公式注入时，按需读取 [`references/csv-injection-official.md`](references/csv-injection-official.md)。

## 工作流

### 1. 定义导入契约

记录模板版本、工作表名、标题行位置、列名、必填项、字段类型、枚举、最大长度、唯一键和允许的空值。模板应带人类可读说明和机器可识别版本，不能只靠列顺序猜字段。

说明整批原子提交还是允许部分成功，以及用户能否重复上传同一文件。

### 2. 识别真实文件

检查文件签名、扩展名、MIME、压缩结构、工作表数量、隐藏表和宏风险。对 CSV 检测 UTF-8、UTF-8 BOM、GBK 等候选编码及分隔符，并在不确定时要求用户确认。

不要仅凭扩展名选择解析器，也不要静默替换无法解码的字符。

### 3. 保留标识符语义

手机号、身份证号、订单号、邮编、银行卡号和外部编码应按字符串处理，保留前导零并拒绝科学计数法造成的精度损失。区分空单元格、空字符串、数值零和文本 `0`。

日期必须明确是文本、Excel 序列值还是带时区时间；记录采用的日期系统、时区和无效日期处理方式。

### 4. 分阶段校验

按顺序执行：文件结构、标题映射、单元格解析、字段规则、跨字段规则、跨行重复、数据库冲突和业务权限。保留原始行号、原值与规范化值，错误信息面向业务人员，不泄露数据库或堆栈细节。

不要在解析阶段就写入正式数据。

### 5. 防止表格公式注入

导出或生成可被 Excel 打开的 CSV 时，识别去除前导空白或控制字符后以 `=`, `+`, `-`, `@` 等危险字符开头的非可信单元格。普通 CSV 引号不能阻止公式执行。

根据目标程序和产品契约选择安全转义、纯文本格式或受控 XLSX 单元格类型，并用实际目标客户端验证。不要破坏本来合法的负数而不说明规则。

### 6. 提供预检与预览

正式写入前显示文件摘要、成功数、错误数、待新增、待更新、重复和关键字段样例。允许下载带原始行号和修复建议的错误清单。

预览必须与最终提交使用同一套解析与校验逻辑，避免“预览通过、导入失败”。

### 7. 保证幂等与恢复

为文件内容、租户、模板版本和业务键设计幂等标识。重复上传、浏览器重试、任务重启或队列重复消费不应产生重复记录。

若允许部分成功，记录每行状态和批次检查点；若要求整批原子性，确保失败不会留下半批数据。明确撤销、补偿和重新提交语义。

### 8. 处理大文件

采用流式读取、分块校验和受控并发，设置行数、列数、单元格长度、压缩比、处理时间和内存限制。后台任务应有进度、取消、超时和失败重试，但重试仍需遵守幂等。

### 9. 建立验证矩阵

至少覆盖多种编码、BOM、前导零、15 位以上数字、空值、公式字符、合并单元格、隐藏行、重复标题、跨行重复、重复上传、处理中崩溃和超限文件。

## 停止条件

- 模板、字段含义或新增/更新规则不明确；
- 不知道部分成功还是整批回滚；
- 需要使用未经脱敏的真实敏感数据；
- 现有脏数据的覆盖或删除策略无人确认；
- 用户要求绕过文件安全、权限或唯一性校验。

## 输出约定

1. **导入契约**：模板版本、字段、类型与业务键。
2. **解析与规范化规则**：编码、数字、日期和空值。
3. **安全与权限控制**。
4. **预检、提交、幂等与恢复流程**。
5. **逐行错误格式与用户修复方式**。
6. **性能限制与验证矩阵**。
7. **仍需产品或数据负责人决定的语义**。

不要把“解析库没有报错”写成“数据已正确导入”。
