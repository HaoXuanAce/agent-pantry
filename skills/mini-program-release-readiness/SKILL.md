# 小程序发布就绪检查

小程序“开发者工具里能跑”与“可以安全提审并上线”之间隔着平台配置、隐私声明、真机权限、服务端环境和可恢复性。本 Skill 把这些事实汇总成明确的发布决定。

## 边界

聚焦代码包、平台配置、后端依赖、隐私授权和发布运行风险。平台主体资质、行业牌照或内容合规需要业务与合规负责人确认，本 Skill 只指出缺口，不给法律结论。

没有明确授权时，不执行上传、提交审核、全量发布或回退操作。

目标为微信小程序时，按需读取 [`references/wechat-official.md`](references/wechat-official.md) 并重新确认当前平台规则。

## 工作流

### 1. 固定发布身份

记录：

- 平台与 AppID；
- 代码版本、Git 提交和构建产物；
- 开发版、体验版、审核版与线上版对应关系；
- 目标后端环境和配置来源；
- 发布负责人、审核账号和时间窗口。

禁止用“本地最新代码”代替可追溯的版本身份。

### 2. 对齐页面与包结构

核对入口页面、分包、独立分包、Tab 配置、路径大小写和资源引用。检查主包与各分包体积、重复依赖、首屏所需资源和低速网络下的加载失败状态。

不要为了通过体积限制临时删除监控、错误提示或必要的兼容代码。

### 3. 核对网络与环境配置

列出 request、upload、download、WebSocket 和业务跳转使用的域名，检查 HTTPS、平台合法域名配置、证书链、环境隔离和超时降级。

确认生产包不会指向测试 API、测试支付商户、内网地址或开发者个人代理。

### 4. 追踪登录与授权

验证临时登录凭证只在服务端换取会话，客户端不持有服务端密钥。覆盖首次进入、会话过期、拒绝授权、重新授权、手机号或用户信息能力失败以及多账号切换。

授权失败必须有可恢复路径，不能用无限弹窗逼迫用户授权。

### 5. 建立隐私接口清单

从代码和依赖实际调用反推隐私能力，逐项对齐平台隐私保护指引、用途说明、触发时机和用户同意状态。重点检查位置、相册、相机、剪贴板、手机号、设备和第三方 SDK。

声明不能只看产品文档；条件分支、公共组件和依赖包中的调用也需要证据。未同意前不得提前调用受约束能力。

### 6. 做真机矩阵

至少包含：

- iOS 与 Android 各一台真实设备；
- 较新与较旧基础库或客户端版本；
- 冷启动、热启动和小程序切后台再返回；
- Wi-Fi、移动网络、弱网和断网；
- 权限允许、拒绝、系统永久拒绝；
- 刘海屏、安全区、系统字体放大和键盘遮挡；
- 分享、扫码、支付、订阅消息等实际使用能力。

开发者工具结果不能替代真机证据。

### 7. 验证版本更新与降级

检查新旧前端与后端在发布窗口内能否共存，缓存数据与本地存储是否可迁移，UpdateManager 或等价机制是否给出合理提示。明确审核失败、发布后故障和后端回滚时的处理路径。

平台回退不等于数据回滚；涉及订单或用户数据时必须另行确认补偿方案。

### 8. 准备审核材料

提供可复现的入口路径、测试账号、功能说明、隐私用途和必要截图。审核账号应是最小权限的专用账号，不应共享生产管理员凭据。

### 9. 给出决定

- **可以提审**：产物身份、平台配置、隐私声明和关键真机旅程有证据。
- **修复后提审**：存在明确、可局部修复的阻断项。
- **暂缓**：环境、资质、隐私或恢复方案存在重大未知。

## 停止条件

- AppID、目标环境或发布提交未知；
- 需要未经批准的生产上传、提审、发布或回退；
- 隐私能力的实际用途无人确认；
- 测试需要真实用户敏感数据或管理员账号；
- 数据变更没有恢复或补偿路径。

## 输出约定

1. **发布决定**：可以提审、修复后提审或暂缓。
2. **版本身份表**：提交、产物、AppID、后端环境。
3. **平台配置与隐私能力差异**。
4. **真机旅程矩阵及证据**。
5. **阻断项**：负责人和最小修复动作。
6. **提审材料清单**。
7. **发布、监控与回退方案**。

“开发者工具预览正常”只能作为一条证据，不能单独支持发布决定。
