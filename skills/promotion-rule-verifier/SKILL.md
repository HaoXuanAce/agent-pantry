# 营销规则验证器

促销故障通常不是一个 if 写错，而是规则顺序、金额精度、时间边界、并发资格和退款语义没有共同契约。本 Skill 先做可执行规则模型，再验证所有边界。

## 边界

处理优惠资格、计价顺序、叠加互斥、配额、库存、退款分摊和用户解释。活动文案、视觉设计、渠道投放和法律意见不在范围内。

若产品规则存在歧义，本 Skill 会列出决策点，不替业务方偷偷选择最有利或最便宜的解释。

## 工作流

### 1. 固定词汇与金额单位

明确原价、成交价、优惠基数、应付、实付、运费、税费、已退款、可退金额和最小货币单位。记录币种、时区、活动日历和舍入方式。

所有计算使用十进制或最小货币单位，不使用二进制浮点直接累计金额。

### 2. 建立规则表

每条活动至少描述：

- 适用用户、门店、渠道、商品与规格；
- 门槛使用原价、折后价还是不含运费金额；
- 优惠形式、上限、次数与总预算；
- 生效时间、时区和边界包含关系；
- 可叠加对象、互斥组和优先级；
- 取消、退款、退券和资格恢复规则。

把“不可与其他优惠同享”拆成可执行的具体互斥关系。

### 3. 定义唯一计算流水线

明确商品级优惠、订单级满减、会员折扣、优惠券、积分、运费和税费的顺序。前端预估、下单服务、支付服务、客服后台和退款服务必须引用同一版本规则或同一权威报价结果。

每次报价返回规则版本、命中项、未命中原因和逐步金额，不只返回最终数字。

### 4. 处理叠加与最优选择

将组合问题限定在允许叠加的候选集合中，定义是自动最优、用户选择还是固定优先级。若多个组合金额相同，指定稳定的决胜规则，保证重复报价结果一致。

避免为了“最优惠”无限枚举，给候选数量和计算时间设置上限。

### 5. 覆盖边界与性质

除示例用例外，验证：

- 门槛前一分、刚好达到和后一分；
- 开始前一刻、开始时、结束边界和跨时区；
- 数量零、最大数量、拆单与合单；
- 优惠后金额不为负；
- 优惠分摊之和等于订单总优惠；
- 同一输入和规则版本得到同一结果；
- 无活动时成交价等于基础计价结果。

### 6. 分离报价与资格占用

“页面显示能抢”不等于已占用库存或优惠资格。明确库存、券配额、用户次数和预算在何时预占、确认、释放和过期。用数据库原子更新、唯一约束或等价一致性机制处理并发。

支付超时、取消、重复请求和消息重放不得重复扣减或返还。

### 7. 定义退款分摊

保存下单时的商品级优惠分摊、舍入差额归属和规则版本。覆盖部分退、整单退、多次退、退运费、赠品、用券后退货以及活动已结束后的退款。

退款不能用当前活动规则重新计算历史订单。

### 8. 建立权威样例与自动测试

与产品、财务或运营确认一组黄金订单，写出逐步计算过程。将规则表生成边界表、组合表、性质测试和并发测试，并比较各消费端结果。

### 9. 给用户可解释结果

前端和客服应能说明为何可用、为何不可用、用了哪些优惠、节省多少和退款如何计算。错误信息不能只写“系统繁忙”来掩盖规则拒绝。

## 停止条件

- 优惠基数、计算顺序、叠加关系或舍入规则无人确认；
- 涉及历史订单但缺少当时规则版本和分摊明细；
- 需要直接修改生产库存、券余额或订单金额；
- 财务、税务或消费者权益解释存在争议；
- 要求通过删掉并发校验来提升秒杀吞吐。

## 输出约定

1. **规则契约与待决策项**。
2. **确定的计算流水线**：逐步金额与舍入。
3. **叠加、互斥和最优选择策略**。
4. **库存、资格和幂等边界**。
5. **退款分摊规则**。
6. **黄金样例、边界表和自动测试矩阵**。
7. **用户与客服可解释文案所需事实**。

不要只给几个“看起来正确”的示例；规则必须能解释边界、并发与退款。
