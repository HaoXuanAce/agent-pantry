# 中国移动端 WebView 验收

内置浏览器不是缩小版 Chrome。同一个 URL 会受到容器版本、桥接生命周期、授权回跳、Cookie 策略、系统键盘和安全区共同影响。本 Skill 用真实容器证据判断页面是否可发布。

## 边界

处理微信、支付宝、钉钉、飞书等 App 内 H5 的集成、验收和故障定位。原生 App 开发、平台商户开户、普通桌面浏览器兼容和单纯视觉改稿不在范围内。

涉及 JSSDK、网页授权或开放平台能力时，先确认平台、接口版本和当前官方文档，不凭旧项目经验拼参数。

微信内网页场景按需读取 [`references/wechat-h5-official.md`](references/wechat-h5-official.md)；其他 App 必须使用对应平台契约。

## 工作流

### 1. 固定容器矩阵

记录 App 名称与版本、iOS 或 Android 版本、设备、网络、入口方式、账号类型、目标环境和完整 URL。区分聊天链接、扫码、菜单、工作台、支付回跳和外部浏览器跳回等入口。

不能用系统 Safari 或 Chrome 的通过结果代替目标 App 内证据。

### 2. 识别能力而非只猜 UA

UA 可以辅助判断容器，但关键功能应检查实际桥接对象、能力探测和 ready 事件。为桥接不存在、初始化超时、用户版本过旧和能力被禁用提供明确降级路径。

不要把 UA 字符串当作权限或能力已经可用的证明。

### 3. 固定签名 URL 与 SPA 路由

记录服务端参与签名的 URL、客户端实际地址、查询参数、编码、代理转发结果和路由变化。严格按当前平台契约处理 hash、重定向和 iOS 首次进入地址等差异。

SPA 使用 `pushState` 或路由跳转后，验证是否需要重新签名、重新配置或保持初始入口地址。签名失败时输出两端 URL 的脱敏差异，而不是反复刷新重试。

### 4. 审查网页授权回路

检查 redirect URI 白名单、state 防伪与绑定、授权 code 的一次性消费、服务端换取会话、回跳参数清理和原始目标恢复。令牌、code 和用户标识不得长期留在 URL、前端日志或分析事件中。

遇到授权循环时逐跳记录状态码、Location、Cookie 写入和最终落点，不用增加重定向次数掩盖问题。

### 5. 验证会话与存储

覆盖 Cookie 的 Domain、Path、Secure、SameSite 和过期策略，以及容器对跨站跳转、第三方 Cookie、隐私模式和进程回收的影响。验证 localStorage 不可用、存储被清理和多账号切换时的恢复。

会话失败必须回到可理解的登录或重试状态，不能无限白屏或跳转。

### 6. 验证桥接生命周期

区分 DOM ready、平台 bridge ready、SDK 配置成功和具体 API 调用成功。检查重复初始化、页面前进后退、切后台再回来和多个组件同时注册事件。

分享、支付、定位、扫码、选图等能力要分别记录成功、取消、拒绝和不可用结果。

### 7. 做移动端交互验收

至少覆盖：

- 刘海、灵动岛、底部手势条与安全区；
- 软键盘弹起、收起和输入框自动滚动；
- 系统字体放大、横竖屏和浏览器工具栏伸缩；
- 返回按钮、侧滑返回、关闭页面和二次确认；
- 长列表、固定按钮、弹层、文件上传和相机权限；
- 弱网、离线、接口超时和从后台恢复。

### 8. 核对网络链路

检查 HTTPS 证书链、API 与静态资源域名、CORS、重定向、代理头、缓存和平台域名配置。比较 App 内与外部浏览器的请求差异，避免把所有失败都归因于“微信缓存”。

### 9. 给出证据化结论

按“平台 × 系统 × 入口 × 核心旅程”列出通过、失败、未测与阻断。每个失败附最短复现路径、截图或网络证据、影响和最小修复动作。

## 停止条件

- 目标 App、系统版本、入口或环境不明确；
- 必须使用真实用户敏感信息或生产管理员账号；
- 需要修改开放平台生产配置但未获授权；
- 官方接口契约与现有实现冲突且版本无法确认；
- 没有目标容器真机，却被要求断言已通过真机验收。

## 输出约定

1. **验收结论**：通过、修复后通过、阻断或未覆盖。
2. **容器矩阵**：App、版本、系统、设备、入口和环境。
3. **签名与授权链路**：逐跳 URL、会话和桥接状态。
4. **交互与网络问题**：附可复现证据。
5. **修复优先级与最小改动**。
6. **降级、监控和回退方案**。
7. **仍需真机确认的事项**。

不要把外部 Chrome 通过写成“微信内已兼容”。
